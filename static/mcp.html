Three conversations, not one

BetweenProtocolCarries
App ↔ MCP clientfunction callsPython objects
MCP client ↔ serverMCP (JSON-RPC 2.0)initialize, tools/list, tools/call
App ↔ LLMChat Completions (HTTPS)messages, tools, tool_calls

The app is the only party in all three. That's why it's called the host.

The two ids

JSON-RPC id (1, 2, 3…) pairs an MCP request with its reply, so several can be in flight at once.

tool_call_id (call_…) pairs the model's tool request with the role:"tool" result.

The app translates between them: model call call_abc → MCP request id: 4 → reply id: 4 → tool message for call_abc.

What to look for

Watch messages grow from turn to turn: the API is stateless, so the whole conversation is resent each time.

finish_reason says tool_calls when the model wants tools run, and stop when it answers.

The last turn uses tool_choice: "none": the tools stay listed, but the model must answer.
